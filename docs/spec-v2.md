# 1. 감정 · 말투 교정 제안 (`TONE_CORRECTION`)

| 항목 | 내용 |
| --- | --- |
| 대상 | **개별** — 감정 격양, 공격적인 문제 표현을 보낸 사람에게만 |
| 기능 성격 | 갈등 중재 |
| 개입 갈래 | 관찰 |

## 사용자 스토리

상대방과 대화 중 감정이 격양되어 평소 사용하는 말투가 아닌 다소 공격적이고 감정적인
말투를 사용한다. kakapo 가 사용자에게 제안을 한다.

## 기능 설명

전송된 메시지에서 **공격 표현**(인신공격·욕설·일반화·비꼼) 또는 **오해 유발 표현**
(마침표 단독·호칭 변화·맥락 없는 단답)이 감지되면, **보낸 사람에게만** 상단 위젯에
① 왜 이 표현이 다르게 읽힐 수 있는지 ② 지금 이어서 보낼 수 있는 대체 문장 1개를 제시한다.

## 기능 플로우

```
[메시지 전송] → [트리거 조건 발동] → [LLM 맥락 판정]
→ [방향 문구 + 대체 문장 생성] → [말한 사람에게만 개별 제시]
```

## 트리거 조건

감정이 격양되고 말투 표현이 갈등을 유발할 것 같은 순간 포착.

| 종류 | 예시 |
| --- | --- |
| 인신공격 · 욕설 | |
| 일반화 화법 | "넌 늘 그런 식이다", "한 번을 안 챙겨주냐" |
| 비꼬는 어투 · 반어법 | "잘한다 ㅋㅋ", "대단하다 정말" |
| 오해 유발 표현 | 평소와 다르게 갑자기 짧아진 표현, 단답, 갑자기 많아진 텍스트 양 |
| 비슷한 말 반복 | "전화 받아" → "받아" → "받으라고" |
| 호칭 변화 | 오빠 → 야, 너는 |

## 사용하는 이전 기억 대화 내역

**[개인별 평소 말투 기준]**

같은 문장이라도 사람마다 뜻이 다를 수 있다. 평소 "ㅇㅇ"를 자주 쓰고 그게 일상화된
커플에게 "ㅇㅇ"은 무례이자 갈등 유발이 아니다. 특정 단어를 기준으로 잡는 게 아니라
**맥락과 함께 그 사람의 평소 대비 변화량으로 판정**한다.

| 측정 항목 | 예시 |
| --- | --- |
| 평소 마침표 사용률 | 평소 3% → 이번 메시지 마침표 종결 |
| 평소 사용 호칭 상위 2개 | '오빠', '자기' → '야' |
| 평소 평균 메시지 길이 | |
| ㅋ 개수 | 평소 3개 → 0개 |
| 평소 이모티콘 사용 빈도 | |
| 과거 갈등 때 쓰는 어휘 패턴 | "이 사람은 화나면 존댓말로 바뀐다" |

**[직전 대화 맥락 — 반어·장난 판별용]**
상대가 지금 무엇에 대해 말하고 있었는지. 맥락에 따라 표현의 의미가 달라진다.

## 작동 방식

**LLM 맥락 판정** — 입력: 문제 문장, 직전 3턴, 개인 기준선, 현재 감정 온도

**방향 문구** — 왜 다르게 읽힐 수 있는지 한 줄
ex) '맨날'이라는 말은 지금 한 번의 일이 아니라 그동안 전부로 들릴 수 있음

**대체 문장** — 지금 이어서 보낼 수 있는 문장 1개. 주어를 '너'에서 '나'로 바꿔
**행동과 감정**만 남긴다.

### 나 전달법의 3~4단계 구성 요소

| 요소 | 내용 |
| --- | --- |
| 상황(사실) | 상대방의 행동이나 객관적 상황을 비난 없이 그대로 |
| 영향 | 그 행동이 나에게 미친 구체적인 피해나 영향 |
| 감정 | 그로 인해 내가 느낀 솔직한 감정이나 생각 |
| 바람 | 상대방이 앞으로 해주었으면 하는 구체적인 요구 |

> "네가 약속 시간에 늦을 때(상황), 내가 기다리느라 시간이 많이 걸리고 힘들어(영향).
> 그래서 많이 속상했어(감정). 다음에는 미리 연락해 주면 좋겠어(바람)."

## 화면 구성

```
화면1 (10%)
  [AI가 대화 상황 요약 진단] : [잠깐 지금 욕설도 쓰시고 너무 공격적이에요.]
  [카카포 안내 문구]         : [대신 이렇게 상대방에 말해보세요.]

화면2 (60%)
  [AI가 대화 상황 요약 진단]
  [카카포 안내 문구]
  [대체 문장 본문]           : ["네가 약속 시간에 늦을 때, 내가 기다리느라 …"]
  [왜 이렇게 말해야 하는지]   : [상대방에게는 '맨날'이라는 말은 지금 한 번의 일이
                              아니라 그동안 전부로 들릴 수 있어요.]
```

## 제약 사항

**복사 버튼은 안 만들기** — 결국 자신이 직접 교정안을 보고 작성해야 의미가 있다.

## 예외

맥락 이해가 중요하다. "와 미친 ㅋㅋ", "야 이 바보야 ㅋ" 같이 비속 표현이 있더라도
맥락에 따라 욕설이 의도가 아닌 경우 필터링이 필요하다.

> ### 워커 노트 — 명세 내부 충돌 2건과 처리
>
> **① 대체 문장 길이.** 제약 사항("복사 버튼 없음 → 직접 보고 작성")과 화면 예시
> (4요소를 다 넣은 긴 문장)가 서로 어긋난다. **짧은 쪽(1~2문장, 45자)으로 확정**했다.
> 복사 버튼이 없다는 제약의 근거가 "보고 외워서 직접 친다"인데, 예시 문장은 외워서 칠
> 길이가 아니다. 규격서 8장의 `alternativeSentence` 예시도 짧은 쪽이다.
>
> **② 진단 문구의 주어.** 화면 예시 "잠깐 지금 욕설도 쓰시고 너무 공격적이에요"는
> 주어가 **사람**이고, 규격서 예시 "현재 표현이 상대방에게 공격적으로 들릴 수 있어요"는
> 주어가 **표현**이다. **규격서 쪽(표현이 주어)으로 확정**했다. `CLAUDE.md` 의
> "대상이 사람이면 안 되고 말이면 된다" 원칙이고, 자기가 쓴 말에 "당신은 공격적이다"라는
> 소리를 들으면 사용자는 말투를 고치는 게 아니라 위젯을 끈다.
>
> **③ 출력이 2개 → 4개로 늘었다.** 기존 구현의 `방향 문구`가 규격서에서
> `situationDiagnosis`(상황 진단)와 `correctionReason`(그렇게 읽히는 이유)으로 갈렸다.
> 덕분에 8단계 미결이던 "(a)감정 짚기 / (b)표현 설명 중 무엇을 쓸지" 분기 문제가 사라졌다 —
> 둘 다 필수 필드가 됐다.

# 2. 데이트 코스 추천 (`DATE_RECOMMENDATION`)

| 항목 | 내용 |
| --- | --- |
| 대상 | 전체 / 개별 |
| 기능 성격 | 관계 어시스턴트 |
| 개입 갈래 | 정보 전달 |

## 사용자 스토리

**[전체]** 상대방과 데이트 관련 대화를 나눈다. 카카포가 두 사람의 이전 대화를 바탕으로
데이트 코스를 추천해준다.

**[개별]** 상대방과 데이트 관련 대화를 나눈다. 카카포가 이전에 상대방이 먹고 싶다고 했던 것,
가고 싶다고 했던 카페를 추천해준다. 사용자는 해당 내용을 바탕으로 상대방에게 제안한다.

## 기능 설명

대화에서 데이트 계획 의도가 감지되면, **두 사람이 과거에 남긴 발화(먹고 싶다·가보고
싶다·저장한 링크)를 최우선 근거로** 장소를 구성해 상단 위젯에 카드로 제시한다.

후보는 MVP 단계에서는 **최대 1개**이며, 카드에 **"왜 이 장소, 코스를 추천했는지"** 를
원문·시점과 함께 표시한다. (예: "지난주에 마라탕 땡긴다고 하셨던 거")

## 기능 플로우

```
[트리거 조건 발동] → [현재 대화 스트림 + 이전 기억 대화 내용 함께 사고]
→ [추천 내용 산출] → [카카오/네이버 지도 정보 탐색] → [정제 후 사용자에게 제시]
```

## 트리거 조건 — 데이트 의도 감지

| 종류 | 예시 |
| --- | --- |
| 명시적 계획 질문 | "어디 갈까", "뭐 먹지", "뭐 하지", "데이트 어디서 해", "오늘 뭐할까", "주말에 뭐해", "만나서 뭐하지" |
| 일정 확정 발화 | "토요일에 보자", "이번 주말에 만나자", "내일 몇 시에 봐", "금요일 시간 돼?", "다음 주에 볼까" |
| 장소·음식 카테고리 언급 | "배고파", "맛집", "카페", "전시", "영화", "산책", "~ 먹고 싶다", "~ 가보고 싶다", "~ 해보고 싶다" |
| 이전 대화 기억의 재언급 | "저번에 그 카페", "우리 가보자던 데", "네가 말한 그거", "먹고 싶다고 했던" |

## 사용하는 이전 기억 대화 내역 — 과거에 남긴 발화

| 종류 | 예시 |
| --- | --- |
| 장소 | "이번주에는 삼각지에서 볼까?", "이 카페 완전 내 스타일이다" |
| 음식 | "시원한 맥주 마시고 싶어", "마라탕 땡긴다" |
| 행동 | "날씨 풀려서 산책하면 좋을 것 같아", "방탈출 재밌대" |
| 일정 | "이번주 토요일", "내일", "20일" |
| 두 사람의 취향 | 귀여운 것을 좋아하는지, 활동적인 것을 좋아하는지, 공통 관심사, 음식 |

→ 위 대화 내용들을 기억·저장했다가 기능 트리거 작동 시 사용한다.

## 작동 방식

기억·저장 대화 내용 바탕 후보지 산출 + 현재 대화 내용 바탕 후보지 산출 → **적합도 스코어링**

1. 과거 나눈 대화 기억에 적합한지
2. 현재 대화 스트림에 적합한지
3. 커플이 데이트하는 날, 시간에 영업·운영을 하는지
4. 날씨 + 시간 + 예산 고려
5. 두 사람의 취향에 적합한지

→ 최종 후보 선정 + 데이트 코스 생성 → 장소 링크 추출·연결 → 추천 이유 문구 생성 → 제시

- 카카오 로컬·지도 API 사용 → 장소 검색
- 핫플·현재 트렌드 데이트 코스 탐색은 어떻게 해야 할지 고민 (미결)
- 자주 사용되는 코스 + 자주 가는 플레이스 데이터셋 사전 구축 **or** 완전히 위임 (미결)

## 화면 구성

```
화면1 (10%)
  [카카포 안내 문구]     : [kakapo가 추천하는 장소와 데이트 코스 가져왔어요]
  [데이트코스 요약, 이름] : [찐 성수 주민 픽 브런치 데이트 코스]

화면2 (60%)
  [카카포 안내 문구]
  [데이트코스 요약, 이름]
  [핵심 장소 이름 + 요약] : [성수 다락] [골목길 3층 건물의 2,3층에 자리한 식당입니다.]
  [데이트 코스 장소 이름] : [성수 다락-식당] - [헤븐센스-소품샵] - [봄의정원-카페] - [서울숲-산책]
  [왜 이 코스를 추천했는지] : ["3주 전에 상대방이 성수 가보고 싶다고 하셨어요. 내일 낮에
                            만나신다고 하신 내용까지 반영해서 …"]
```

## 제약 사항

대화 스트림은 커플만의 공간이며 침범하지 않는다.

## 예외

- 장소·음식·일정·취향·행동 중 없는 정보가 존재할 시 해당 정보를 제외하고 스코어링 진행
- 기억·저장된 이전 대화 내역이 없을 경우: 현재 대화 스트림 + 인기 데이트 코스로 추천

> ### 워커 노트 — 구현 범위
>
> **적합도 스코어링 5개 중 ①②⑤만 구현했다.** ③영업시간은 카카오 로컬 API 가 주지 않고
> (크롤링 영역), ④날씨·예산도 데이터 소스가 없다. 데모에서 티가 나지 않는 항목이다.
>
> **장소는 카카오 로컬 API 로만 가져온다. LLM 은 상호명을 만들지 않는다.**
> 규격서 9장의 `externalUrl` 이 필수 필드라, LLM 이 "성수다락"을 지어내면 존재하지 않는
> 가게와 죽은 링크가 그대로 화면에 뜬다. 역할을 이렇게 갈랐다.
>
> | LLM | 카카오 |
> | --- | --- |
> | 어느 지역에서 무엇을 검색할지, 코스 의도, 추천 이유 | 실제 상호명, 카테고리, `place_url` |
>
> **"완전히 위임 vs 데이터셋 사전 구축" 은 위임 쪽으로 갔다.** 카카오 REST API 키만
> 있으면 되고 시연 지역이 바뀌어도 대응된다. 다만 "핫플·트렌드"는 카카오가 알려주지
> 않으므로 미해결로 남는다 — PM 결정 필요.
>

# 3. 유튜브 영상 추천 (`YOUTUBE_RECOMMENDATION`)

| 항목 | 내용 |
| --- | --- |
| 대상 | 전체 / 개별. 관계 고민·갈등 상황 → **개별 전달** (같은 영상을 둘 다 보낼 case 도 존재 가능) |
| 기능 성격 | 갈등 중재 |
| 개입 갈래 | 정보 전달 |

## 사용자 스토리

상대와 다투고 나서 어떻게 풀어야 할지 모르겠다. kakapo 가 지금 상황과 비슷한 고민을 다룬
연애 유튜브 영상을 하나 가져다준다. 영상을 보고 내가 어떻게 해야 할지 감을 잡는다.

## 기능 설명

대화에서 **관계 고민 신호** 또는 **공통 관심 주제**가 감지되면, 상황에 맞는 유튜브 영상
**1개**를 상단 위젯에 카드로 제시한다.

영상은 제목·썸네일만으로 고르지 않는다.
**베스트 댓글 3개를 함께 읽어 영상이 실제로 무엇을 말하는지 확인한 뒤** 선택한다.

## 기능 플로우

```
[트리거 조건 발동] → [고민 유형 / 관심 주제 분류] → [검색어 생성]
→ [유튜브 검색 + 베스트 댓글 3개 수집] → [상황 적합도 검증]
→ [영상 1개 선정 + 근거 문구 생성] → [정제 후 사용자에게 제시]
```

## 트리거 조건 — 관계 고민 신호 (개별 노출)

① 갈등 직후 · 냉각기
② 사과 의향은 있는데 방법을 모름
③ 반복되는 같은 갈등
④ 관계 자체에 대한 회의
⑤ 상대를 이해 못 하겠다는 표현

> LLM 을 통한 스트림 내 대화 맥락 이해가 사실 제일 중요해 보입니다. (PM)

## 사용하는 이전 기억 대화 내역

| 데이터 | 예시 |
| --- | --- |
| 현재 스트림 내 대화 | |
| 반복된 갈등 주제 | 연락 빈도, 약속 취소, 이성 친구, 돈 |
| 직전 갈등의 원인 발화 | "왜 답장을 안 해" |
| 관계 단계 추정 | 100일 언급, 1년 언급, 첫 만남 시점 → 연애 초반과 장기 커플은 필요한 콘텐츠가 다름 |
| 갈등에서 취하는 태도 | 회피형인지 추궁형인지 |
| 이미 추천했던 영상 이력 | 같은 영상·같은 유형 재추천 방지 |

## 작동 방식

**고민·유형 분류 (LLM)** — 현재 대화 + 이전 기억 대화 내역을 입력해 유형을 하나로 특정
`연락 / 다툼 후 화해 / 서운함 표현 / 권태 / 신뢰 / 이해 부족 / 사과`

**검색어 생성** — 유형 + 관계 단계를 조합해 한국어 검색어
ex) `연인 사과하는 법`, `연락 문제 다툼 해결`, `권태기 극복`

**유튜브 검색** — 채널 선정은 필수적일 것이라고 생각함
**후보 필터링** → **베스트 댓글 3개로 맥락 검증**

**근거 문구 생성 (LLM 1회)** — 왜 이 영상인지 한 줄. 관계 상태를 진단하지 않는 표현으로.
ex) "비슷한 상황을 다룬 영상이라 가져와봤어요"

  [왜 이 영상인지]   : [여사친으로 인한 다툼을 슬기롭게 해결하는 방법에 대한 영상이에요.]

화면2 (60%)
  [카카포 안내 문구]

  [영상 제목]
  [채널명]
  [왜 이 영상인지] : [현재 커플 대화 상태 + 영상과의 연결점 + 영상을 봤을 때]

"이렇게 하면 해결돼요"(X) / "비슷한 상황을 다룬 영상이에요"(O)

## 예외

- **검색 결과 0건 / 후보 전원 탈락** → 추천하지 않고 침묵한다. 아무 영상이나 던지지 않는다
- **댓글이 비활성화된 영상** → 맥락 검증을 못 하므로 후보에서 제외

> ### 워커 노트 — 규격서와 충돌하는 지점
>
> **`videoSummary` 문제는 명세 수정으로 해소됐다.** 화면에서 `[영상 요약 정보]` 가 빠지면서
> 이 필드를 쓸 자리가 없어졌다. 원래 문제는 규격서 10장이 "PM 데이터셋 값만 반환, AI 생성
> 금지"로 정의했는데 명세는 실시간 검색이라 데이터셋에 없는 영상만 나온다는 것이었다.
> 실측에서도 선정된 영상의 description 길이가 0이었다.
> **규격서는 고치지 않기로 했다** — 선택 필드라 프론트가 안 쓰면 그만이고, 규격 변경은
> 서버 쪽 작업을 만든다 (`docs/contract-review.md` "서버 작업이 필요 없는 것").
> 코드는 값이 있으면 채우고 없으면 생략한다 — 백엔드가 저장해 두고 싶을 수 있어서 남겼다.
>
> **근거 문구가 3요소 구조로 늘었다.** `현재 상황 + 영상과의 연결점 + 보고 나면 알게 되는 것`.
> ①에 **관계 규정이 새어들 위험**이 커져서 `yt_pick.md` 에 경계 표를 넣었다 —
> "사과하고 싶은데 말이 안 나올 때"(상황, 허용) vs "요즘 대화가 줄어든 상황이라"(규정, 금지).
> 같은 명세 안에 "관계 상태를 진단하지 않는 표현으로"가 그대로 남아 있어 이 해석이 맞다고 봤다.
>
> **검색어에 '권태기'를 쓰지 않게 막았다.** 검색어 자체는 사용자에게 안 보이지만, 그 단어로
> 찾은 영상은 제목에 '권태기'가 박혀 있고 그 제목이 화면에 그대로 뜬다. 절대 제약이 깨진다.
> 같은 이유로 **금지어 하드 필터가 영상 제목·설명까지 검사**한다.
>
> **"이미 추천했던 영상 이력"을 지킬 수단이 없다.** 워커는 동기 REST 요청마다 상태가
> 없고, 규격서 요청에 과거 추천 이력이 들어오지 않는다. 서버 담당자에게 필드 추가를
> 요청한 상태다 (`docs/contract-review.md` 참조).
>
> **말투 교정이 발동한 요청에서는 유튜브 추천을 보류한다.** 둘 다 갈등 중재지만 시점이
> 다르다 — 말투 교정은 방금 보낸 메시지에 붙고, 영상 추천은 명세상 **냉각기**에 주는
> 기능이다. 방금 공격적인 메시지를 보낸 사람에게 교정 제안과 영상이 동시에 뜨면 훈계가 된다.
> `router.py` 의 `SUPPRESS_YOUTUBE_WHEN_TONE` 상수로 끌 수 있다.
