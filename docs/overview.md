# kakapo AI 워커

> 커플의 채팅을 분석해서 **언제 끼어들지**와 **뭘 띄울지**를 정하는 판정 엔진
> 레포: https://github.com/2026-likelion-ssu-hackathon/AI_worker

---

## 뭘 하는 물건인가

채팅 대화를 넣으면 위젯에 띄울 내용을 뱉는다. 아무것도 안 띄우는 것도 결과다.

```
채팅 대화  →  [AI 워커]  →  위젯 페이로드 (또는 "개입 안 함")
```

**위젯 슬롯은 1개다.** 여러 기능이 동시에 발동해도 하나만 나간다.

---

## 지금 되는 것 — 후보 기능 2개

| | 기능 | 언제 뜨나 | 누구에게 |
| --- | --- | --- | --- |
| 1 | **갈등 중재** | 공격적·오해 유발 표현을 보냈을 때 | 보낸 사람에게만 |
| 2 | **대화 소재 제시** | 대화가 겉돌 때 | 둘 다 / 한 명 |

갈등 중재가 우선이다. 싸우는 중에 "요즘 듣는 노래 있어요?"를 띄울 순 없다.

## 실제로 이렇게 나온다

### 대화 소재 — RAG로 예전 기억을 꺼낸다

A가 지하철에서 있었던 웃긴 일을 혼자 떠들고 B는 `ㅋㅋ`, `ㅇㅇ`만 하는 상황

```
트리거   한쪽만 발화 (A 91% / B는 리액션만 100%)
scope    A에게만
소재     "5월 9일 지하철 종점까지 갔던 날, 기억나세요?"
근거     5월 9일 두 분이 지하철로 다녀오신 일이에요
```

지하철 얘기를 하고 있으니 **예전에 둘이 지하철에서 졸다 종점까지 간 기억**을 꺼냈다.
최신순으로 뽑았으면 절대 안 나올 결과다. 이게 "AI가 진짜 듣고 있다"는 느낌을 만든다.

### 갈등 중재 — 대체 문장을 제시한다

B가 약속을 취소하자 A가 화가 난 상황

```
감지     일반화 화법 '맨날'
         호칭 변화 — 평소 '오빠, 자기' → '야, 너'
         평소와 다름 — 마침표 3%→종결 / ㅋ 2.8개→0개 / 이모지 35%→없음
판정     진짜 갈등 (장난 아님), 감정 온도 = angry

scope    A에게만 (B는 이런 게 떴다는 것도 모른다)
방향     '맨날'은 지금 한 번이 아니라 그동안 전부로 들릴 수 있어요
대체문장 "오빠 오늘 못 온다니까 나 좀 서운했어, 다음엔 미리 말해줘"
```

### 안 띄우는 것도 기능이다

| 상황 | 결과 |
| --- | --- |
| "야 이 바보야 ㅋㅋ" (장난) | **개입 안 함** |
| "나 지금 회의라 이따 톡할게" (진짜 바쁨) | **개입 안 함** |

똑같이 비속 표현인데 하나는 뜨고 하나는 안 뜬다. 단어를 보는 게 아니라 맥락을 본다.

---

## 판정의 핵심 — 개인별 기준선

**같은 말도 사람마다 뜻이 다르다.**

평소 `ㅇㅇ`만 보내는 사람의 `ㅇㅇ`은 무례가 아니다.
원래 서로 "야"라고 부르는 커플에게 "야"는 호칭 변화가 아니다.

그래서 특정 단어를 기준으로 잡지 않고 **그 사람의 평소 대비 변화량**으로 판정한다.

| 측정 항목 | 예시 |
| --- | --- |
| 마침표 사용률 | 평소 3% → 이번 메시지 마침표 종결 |
| 사용 호칭 상위 2개 | '오빠', '자기' → '야' |
| ㅋ 개수 | 평소 2.8개 → 0개 |
| 이모티콘 빈도 | 평소 35% → 없음 |
| 평균 메시지 길이 | |
| 갈등 시 어휘 패턴 | "이 사람은 화나면 존댓말로 바뀐다" |

실제로 "야 이 바보야 ㅋㅋ"를 장난으로 판정한 근거가 이거였다.

> "직전 대화가 가볍고 양측 ㅋㅋ 사용, **B의 화난 패턴(존댓말·말수 증가)과 불일치**해 장난으로 보임"

## 절대 제약

**관계 상태를 언급하는 문구는 절대 출력하지 않는다.**

```
❌ "요즘 대화가 줄었어요"
❌ "권태기 같아요"
❌ "두 분 사이가 서먹해 보여요"
```

누군가에게 "너네 권태기다"라는 말을 들으면 의식이 심해지고, 평소 하지 않던 생각까지 하게 되어
오히려 관계가 나빠진다. **내가 눈치채기 전에 kakapo가 먼저 눈치채고 조용히 회복시킨다** — 이게 서비스의 핵심이다.

그래서 **감지하는 부분과 말하는 부분이 완전히 분리돼 있다.**
트리거는 갈등·권태를 감지하지만, 출력은 그걸 절대 드러내지 않는다.
프롬프트에만 맡기지 않고 코드에서 문자열 검사로 한 번 더 막는다.

**단, 갈등 중재에서 감정을 짚는 건 괜찮다.** "지금 감정이 올라와 있는 것 같아요"는 허용된다.
금지 대상은 *관계를 규정하는 말*이지 감정 언급 전부가 아니다. 그 화면은 상대에게 안 보이고,
본인도 이미 아는 상태다.

시연용 대화 8개로 전부 확인했다.

| 케이스 | 상황 | 결과 |

| case1 | 단답 핑퐁 | 소재 (둘 다) |

| case3 | 한쪽만 발화 | 소재 (A에게) |
| case4 | 매일 같은 대화 반복 | 소재 (둘 다) |

## 팀별 확인 부탁드립니다

### 프론트 (민상)

**`kind` 값에 따라 화면 배치가 다릅니다.** 응답 스키마:

```json
{
  "kind": "topic",
  "scope": "individual",
  "target": "A",
  "content": "5월 9일 지하철 종점까지 갔던 날, 기억나세요?",
  "reason": "5월 9일 두 분이 지하철로 다녀오신 일이에요"
}
```

| `kind` | 중앙 (크게) | 보조 (작게) |
| --- | --- | --- |
| `topic` | `content` — 대화 소재 | `reason` — 근거 문구, **아래** |
| `tone` | `content` — 대체 문장 | `reason` — 방향 문구, **위** |

`reason`이 `null`일 수 있습니다 (기억 없이 오늘의 질문으로 나간 경우).

### 디자인 (혜원)

**갈등 중재 화면에는 복사 버튼을 넣지 않습니다.** 명세에 있던 제약인데,
직접 보고 타이핑해야 의미가 있다는 판단입니다. 그래서 대체 문장은 짧게 나오도록 맞췄습니다.

위젯은 슬롯 1개이고, 새 내용이 오면 이전 걸 교체합니다.

### 채팅 서버

**위젯은 수신자별로 갈라서 보내주셔야 합니다.**

`scope`가 `"individual"`이면 `target`인 사람에게만 갑니다.
방 단위 브로드캐스트하면 개별 코멘트가 양쪽에 다 떠서 기능이 깨집니다.

특히 갈등 중재는 상대에게 보이면 그 순간 싸움이 커집니다.

> 기존 `contract-v2.md`는 방 구조가 바뀌면서 폐기됐습니다. **새 계약서 재합의가 필요합니다.**

### PM (영환)

- 나머지 후보 기능 명세 부탁드립니다. 라우터에 끼우기만 하면 되는 구조로 만들어뒀습니다
- 갈등 중재의 방향 문구를 어느 쪽으로 할지 미결정입니다
  - (a) 감정 짚기 — "지금 감정이 조금 올라와 있는 것 같아요"
  - (b) 표현 짚기 — "'맨날'은 그동안 전부로 들릴 수 있어요"
  - 지금은 모델이 상황에 맞춰 고릅니다. 화났을 때는 (a)를 우선하도록 고정할 수도 있습니다

## 돌려보려면

```bash
git clone https://github.com/2026-likelion-ssu-hackathon/AI_worker.git
cd AI_worker

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # OPENAI_API_KEY 채우기

.venv/bin/python -m tools.run fixtures/case7_tone.json --verbose --no-persist
```

`--verbose`를 붙이면 왜 그렇게 판정했는지 중간 과정이 다 보입니다.
`--no-persist`는 반복 실행용입니다 (안 붙이면 쓴 기억이 소모돼서 두 번째부터 다른 게 나옵니다).

코드 설명은 레포의 `README.md`에 있습니다.
