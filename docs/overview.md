# kakapo AI 워커

> 커플의 채팅을 분석해서 **언제 끼어들지**와 **뭘 띄울지**를 정하는 판정 엔진
> 레포: https://github.com/2026-likelion-ssu-hackathon/AI_worker

---

## 뭘 하는 물건인가

채팅 대화를 넣으면 위젯에 띄울 내용을 뱉는다. 아무것도 안 띄우는 것도 결과다.

```
채팅 대화  →  [AI 워커]  →  위젯 페이로드 (또는 "개입 안 함")
```

입출력은 **백엔드 연동 규격 v1** 그대로다. 요청·응답 JSON 은 `docs/contract-v1.md`.

---

## 지금 되는 것 — 후보 기능 3개

| | 기능 | 언제 뜨나 | 누구에게 |
| --- | --- | --- | --- |
| 1 | **갈등 중재 (말투 교정)** | 공격적·오해 유발 표현을 보냈을 때 | 보낸 사람에게만 |
| 2 | **데이트 코스 추천** | 데이트 계획 얘기가 나올 때 | 둘 다 / 한 명 |
| 3 | **유튜브 영상 추천** | 관계 고민 신호가 있을 때 (냉각기) | 주로 한 명 |

**대화 소재 제시**는 우선순위에서 밀려 파킹했다. 코드는 `parked/` 에 그대로 있고
언제든 되살릴 수 있다.

## 실제로 이렇게 나온다

### 갈등 중재 — 보낸 사람에게만 조용히

A가 `"야 너는 맨날 그런 식이야."` 라고 보낸 직후. **B 화면에는 아무것도 안 뜬다.**

```
TONE_CORRECTION   INDIVIDUAL → USER_A

  진단   지금 표현이 평소보다 세게 나갔어요
  안내   대신 이렇게 상대방에게 말해보세요.
  대체   "자기 오늘 못 온다니 좀 서운했어, 다음엔 미리 말해줘"
  이유   '맨날'이 그동안 전부를 탓하는 말로 들려요
```

이걸 잡아낸 근거:

```
[generalization]  일반화 화법 '맨날'
[address_change]  평소 '오빠, 자기' → '너, 야'
[abrupt_change]   마침표 3%→종결 / ㅋ 2.8개→0개 / 이모지 35%→없음
```

**같은 문장이라도 사람마다 다르게 판정한다.** 원래 호칭이 "야"인 커플에게 "야"는
호칭 변화가 아니다. 절대 기준이 아니라 **그 사람의 평소 대비 변화량**으로 본다.

### 안전장치 — 똑같이 욕이 있어도 장난이면 침묵

```
B: 야 이 바보야 ㅋㅋㅋ

→ SKIPPED  (개입하지 않음)
   · 맥락 판정 — 갈등이 아님 (장난)
```

`insult` 룰에 그대로 걸리지만 LLM 맥락 판정이 걷어낸다.
**여기서 잔소리가 뜨면 사용자는 앱을 지운다.** 애매하면 개입하지 않는 게 기본값이다.

### 데이트 코스 — 예전에 한 말을 근거로

```
DATE_RECOMMENDATION   COUPLE

  코스   성수 브런치 데이트 코스
  요약   브런치 먹고 소품샵 구경한 뒤 서울숲까지 걷는 코스
  1.     (실제 상호)   [RESTAURANT]
  2.     (실제 상호)   [SHOP]
  이유   3주 전에 성수 가보고 싶다고 하신 얘기랑
         이번 주 토요일에 만나신다는 대화를 반영했어요
```

**장소는 카카오 지도에서 가져온다. AI 가 상호명을 만들지 않는다.**
지어내면 존재하지 않는 가게와 죽은 링크가 그대로 화면에 뜨기 때문이다.

| AI 가 하는 일 | 카카오가 하는 일 |
| --- | --- |
| 어느 지역에서 무엇을 검색할지, 왜 이 코스인지 | 실제 상호명, 카테고리, 지도 링크 |

### 유튜브 — 댓글까지 읽고 고른다

**제목·썸네일만 보고 고르지 않는다.** 연애 유튜브는 제목이 자극적이고 내용이 딴판이다.
화해하고 싶은 사람에게 "이런 남자는 걸러라" 영상을 던지면 상황만 나빠진다.

그래서 후보마다 **베스트 댓글 3개**를 같이 읽고, 영상이 실제로 무슨 결론인지 확인한 뒤 고른다.
적합한 게 없으면 아무것도 안 띄운다.

## 절대 지키는 것

**관계 상태를 언급하는 문구를 절대 출력하지 않는다.**

```
❌ "요즘 대화가 줄었어요"    ❌ "권태기 같아요"    ❌ "두 분 사이가 서먹해 보여요"
```

"너네 권태기다"라는 말을 들으면 의식이 심해져서 오히려 관계가 나빠진다.
**내가 눈치채기 전에 kakapo가 먼저 눈치채고 조용히 회복시킨다** — 이게 서비스의 핵심 가치다.

그래서 **감지와 발화가 완전히 분리돼 있다.** 트리거는 갈등·권태를 감지하지만,
출력은 그걸 절대 드러내지 않는다. 프롬프트로만 막지 않고 **문자열 하드 필터로 강제**한다.

필터는 **유튜브 영상 제목까지** 검사한다. 우리가 쓴 문장이 아니어도
"권태기 극복법"이라는 제목이 위젯에 박히면 똑같이 깨지기 때문이다.

### 헷갈리기 쉬운 경계

| | 예시 | |
| --- | --- | --- |
| ❌ 관계 규정 | "요즘 대화가 줄었어요", "권태기" | 모든 기능에서 금지 |
| ✅ 감정 알아봄 | "지금 감정이 조금 올라와 있는 것 같아요" | 말투 교정에서는 이게 기능이다 |

말투 교정에서도 **사람은 평가하지 않는다.** "무례하시네요"는 안 되고,
"공격적으로 들릴 수 있어요"는 된다. 대상이 사람이면 안 되고 말이면 된다.

## 다른 파트에 필요한 것

### 서버 (채팅 서버 담당)

**위젯은 수신자별로 갈라서 보내야 한다.** 방 단위 브로드캐스트만 하면
개별 결과가 양쪽에 다 떠서 위 설계가 통째로 깨진다.

```
visibilityType = INDIVIDUAL  →  targetParticipant 에게만
visibilityType = COUPLE      →  두 명 모두
```

확인 요청 사항은 `docs/contract-review.md` 에 항목별로 정리해뒀다. 특히 두 가지가 급하다.

- 요청에 **최근 추천 이력**이 필요하다 — 없으면 "같은 영상 재추천 방지"를 지킬 수 없다
- 요청에 **화자별 말투 프로필**이 필요하다 — 없으면 "평소 대비 변화량" 판정이 무력화된다

### 프론트 (민상)

- `resultType` 별로 화면 배치가 다르다 (`TONE_CORRECTION` / `DATE_RECOMMENDATION` / `YOUTUBE_RECOMMENDATION`)
- **위젯 슬롯이 1개인지 결정 필요.** 규격서는 여러 결과 동시 반환을 허용한다.
  워커는 우선순위 순으로 정렬해 보내므로, 하나만 쓸 거면 `results[0]` 을 쓰면 된다

### 디자인 (혜원)

- 말투 교정에 **복사 버튼을 만들지 않는다.** 직접 보고 타이핑해야 의미가 있다는 명세 제약이다
  (그래서 대체 문장을 45자 이내로 짧게 뽑는다)
- `guideMessage` 고정 문구 3종이 `worker/copy.py` 에 있다. 문구 주인은 디자인·PM이다

### PM (영환)

- **감정 분석 기능 명세** — 규격서 11장이 비어 있다
- 데이트 코스의 **"핫플·트렌드" 탐색 방법** — 명세에 미결로 남아 있다

## 기술적으로 자랑할 만한 것

**1. 개인별 말투 기준선.** 특정 단어를 금지어로 두지 않는다. 평소 "ㅇㅇ"를 쓰는 커플에게
"ㅇㅇ"은 무례가 아니다. 마침표율·호칭·길이·ㅋ 개수·이모지 빈도의 **변화량**으로 판정한다.

**2. 감지와 발화의 분리.** 트리거는 갈등을 잡지만 출력은 그걸 절대 드러내지 않는다.
이 분리가 설계 난이도의 대부분이다.

**3. 환각을 구조로 막았다.** LLM 은 "무엇을 찾을지"까지만 정하고,
실제 이름·링크는 외부 API 가 준 것만 쓴다. 지어낼 여지 자체를 없앴다.

**4. 침묵이 기본값.** 애매하면 개입하지 않는다. 안 띄우는 것도 결과다.
