대화를 **화제 단위**로 끊는다.

세그먼트란 같은 화제로 이어지는 연속 메시지 묶음이다. 화제가 바뀌는 지점에서 자른다.

## 자르는 기준

**화제가 바뀌었는가.** 그것 하나만 본다.

- 앞뒤가 같은 일에 대해 말하고 있으면 한 세그먼트다
- 다른 일로 넘어갔으면 자른다
- 화제가 하나뿐이면 세그먼트도 하나다. **억지로 쪼개지 않는다**

## 자르지 않는 것 — 말투와 감정

**말투가 변한 것은 경계가 아니다.** 같은 화제 안에서 감정은 얼마든지 변한다.

```
A: 오빠 오늘 몇 시에 와? 저녁 같이 먹으려고 기다리고 있었어
B: 아 미안 오늘 야근 잡혀서 못 갈 것 같아
A: 또? 지난주에도 그랬잖아
A: 야 너는 맨날 그런 식이야.
```

호칭이 `오빠` 에서 `야` 로 바뀌고 말투가 굳었지만 **처음부터 끝까지 저녁 약속 얘기 하나다.**
세그먼트는 1개다. 여기서 자르면 뒤에 오는 판단이 "왜 화가 났는지"를 못 보게 된다.

감정 변화는 자르는 대신 `mood` 에 적는다.

## 경계 판단이 애매할 때

**자르지 않는 쪽으로 기운다.** 잘못 자르면 뒤 단계가 맥락을 잃지만, 안 자르면 기존과
같아질 뿐이다. 확실히 다른 일로 넘어갔을 때만 자른다.

## 출력

- `message_ids` — 그 세그먼트에 속한 메시지 id. **주어진 id 만 쓴다**
- **모든 메시지가 정확히 한 번씩** 어느 한 세그먼트에 들어가야 한다.
  빠뜨리지 않고, 중복해서 넣지 않고, 순서를 지킨다
- `topic` — 화제를 가리키는 짧은 내부 라벨 (20자 이내)
- `mood` — `light` / `neutral` / `tense` / `heavy` 중 하나

### topic 을 쓸 때 — 관계 상태를 규정하지 않는다

`topic` 은 **무엇에 대한 대화인지**만 적는다. 두 사람의 관계가 어떤 상태인지 판정하지 않는다.

- ✅ `"주말 약속"`, `"연락 문제로 다툼"`, `"저녁 메뉴"`, `"회사 얘기"`
- ❌ `"권태기 조짐"`, `"요즘 대화가 줄어든 것에 대한 다툼"`, `"사이가 서먹해진 상황"`

JSON 으로만 답한다. 설명을 덧붙이지 않는다.
